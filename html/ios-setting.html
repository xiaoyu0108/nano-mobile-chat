      服务端地址（换自己的 Worker 时才改）
      

        
        
        

          
          
        

        
「还原初始」会把服务端地址恢复成默认 Worker，并重新生成一枚 pk（所以旧 pk 一定会变）；还原后要重新复制快捷指令里的地址 / 令牌 / JSON。如果 Worker 设了 PEEK_TOKEN，还要把 Worker 的 secret 改成新 pk；公用模式（PEEK_PUBLIC=1）不用改 Worker。
这个地址会同时用于「窥屏」和「Web Push」。保存后去 设置 → 其他 → Web Push 点一次「开启 / 重新订阅」；VAPID 公钥会自动从 Worker 的 /vapid 获取。
默认用作者的公用 Worker 就能玩；如果经常失败、额度不足，或想和朋友隔离数据，可以换成自己的 Worker，详细步骤见下面的 「自己部署 Worker（详细教程）」。
给其他人公用时，在 Worker 里设置 PEEK_PUBLIC=1，每个浏览器的令牌会把数据彼此隔离。
公用模式不会使用站长的模型 API：每个人都要在自己的 Nano 里配置主 API，否则只会收到“请先配置你自己的 API”的提示。

      

    


    

      自己部署 Worker（详细教程）
      

        

          
默认用作者的 Worker 就能玩。如果你经常遇到慢、额度不足，或者想和朋友隔离数据，就按下面部署一个自己的。部署一次，窥屏和 Web Push 都会走你的 Worker。


          
          
复制后发给任意 AI（ChatGPT / Claude / 豆包等），让它按「电脑」或「只用手机」一步一步教你。下面也有一份手动步骤。

          

          

            
单文件源码（手机部署用，依赖已打包）

            https://raw.githubusercontent.com/xiaoyu0108/nano-mobile-chat/main/push-worker/dist/index.js
            
手机打开这个链接，全选复制内容，粘贴到 Cloudflare 的 Worker 代码编辑器。不要用 src/index.js 手动粘贴，它带 import，控制台会报错。
这个单文件版和作者当前 Worker 是同一份代码：/peek、/peek/pending、/vapid、/subscribe 路由完全一致。不要改路由名，也不要把 KV 绑定名改成别的。

          


          
0. 准备

          
    
            
  • 一个 Cloudflare 账号（免费，不用买域名）
    • 
            
  • Node.js 18+（安装时一路下一步）
    • 
            
  • 能打开 PowerShell / Terminal
    • 
          


          

            
1. 安装 wrangler 并登录

            
npm i -g wrangler
wrangler login

          

          
登录会打开浏览器，点 Allow。装完如果提示找不到 wrangler，关掉终端重新打开；还不行就用 npx wrangler login。


          

            
2. 拿代码并安装依赖

            
git clone https://github.com/xiaoyu0108/nano-mobile-chat.git
cd nano-mobile-chat/push-worker
npm install

          

          
不会用 git 就去 GitHub 点 Code → Download ZIP，解压后进入 push-worker 目录。


          

            
3. 建自己的 KV，记下 id

            
wrangler kv namespace create PUSH_KV

          


          
4. 改 wrangler.toml

          
必须删掉作者的 routes 和 D1，把 name、KV id 换成你自己的。最小可用配置：

          

            
wrangler.toml

            
name = "nano-push-你的名字"
main = "src/index.js"
compatibility_date = "2025-01-01"
workers_dev = true

kv_namespaces = [
  { binding = "PUSH_KV", id = "你刚才的KV_ID" }
]

          

          
PUSH_KV 这个名字不要改。想用自己的域名再加 routes；不需要 D1 / 定时任务就删掉对应块，代码会自动回退到 KV。

          
想带更多人，可以保留 D1：执行 wrangler d1 create nano-db-你的名字，把返回的 database_id 填进 [[d1_databases]]，binding 保持 nano_db。


          

            
5. 设置密钥

            
wrangler secret put PEEK_PUBLIC
# 输入：1

# 可选：保护 /send、/schedule
wrangler secret put PUSH_TOKEN

          

          
VAPID 不用手动配，Worker 第一次访问 /vapid 会自动生成。模型 API 也不用配，Nano 打开聊天时会同步。


          

            
6. 部署

            
wrangler deploy

          

          
记下输出的地址，形如 https://nano-push-你的名字.xxxx.workers.dev。浏览器打开 你的地址/vapid，能看到 key 就正常。


          
7. 填进 Nano

          
    
            
  1. 回到上面的 服务端地址，粘贴你的 Worker 地址；
    2. 
            
  2. 如果第 5 步设了 PUSH_TOKEN，在下面的「Web Push 的 PUSH_TOKEN」填同一个值；没设就留空；
    3. 
            
  3. 点 保存配置；
    4. 
            
  4. 本页会更新接口地址 / 令牌 / JSON，按新值更新快捷指令；
    5. 
            
  5. 去 设置 → 其他 → Web Push 点 开启 / 重新订阅。
    6. 
          


          
8. 验证

          
    
            
  • /vapid 能返回 key；
    • 
            
  • 运行窥屏快捷指令能收到回复；
    • 
            
  • 回到 Nano 私聊能看到这一轮；
    • 
            
  • Web Push 显示「已开启」；
    • 
            
  • Cloudflare → Workers → 你的 Worker → Logs 能看到 POST /peek。
    • 
          


          
9. 能带多少人

          
    
            
  • 纯 KV 自建（上面最小配置）：免费版约 1,000 写/天，约 10~30 个活跃用户；
    • 
            
  • 保留 D1（作者默认配置）：免费 D1 约 10 万行写/天，保守可带 100~300 个活跃用户；
    • 
            
  • 经常跑「重复 50」或很多人同时用，人数要往下压；
    • 
            
  • 到 Cloudflare 看用量，接近 70%~80% 就让重度用户自己部署，或升级 Workers Paid。
    •
